## `search` Method

Perform a search.

For AI answers, RAG, and search previews, use ``contents={"highlights": True}``
and read each result's ``highlights`` list. Exa dynamically chooses the
number of characters based on each document's relevance to your query.
No manual character budget is needed. Set ``max_characters`` only when
your application requires a specific numeric character limit; otherwise
keep ``highlights=True``. Do not use the deprecated ``num_sentences`` or
``highlights_per_url`` options.

Request text when you need full-page content, or use contents=False for
titles and URLs only. Omitting contents still returns text with 10,000
max characters by default.

### Input Example

```python
# Query-relevant passages for AI context
result = exa.search(
  "hottest AI startups",
  num_results=2,
  contents={"highlights": True}
)
for source in result.results:
    print(source.url, source.highlights)

# Deep search with query variations
deep_result = exa.search(
  "blog post about AI",
  type="deep",
  additional_queries=["AI blogpost", "machine learning blogs"],
  num_results=5
)
```

| contents | Optional[Union[[ContentsOptions](#contentsoptions), Literal[False]]] | Options for retrieving page contents. Defaults to `{"text": {"maxCharacters": 10000}`}. Use False to disable contents. For AI context, prefer `{"highlights": True}` for relevance-based sizing and read result.highlights. See [ContentsOptions](#contentsoptions) for all options. | None |
| num_results | Optional[int] | Number of search results to return. Default 10. | None |
| include_domains | Optional[List[str]] | Domains to include in the search. | None |
| exclude_domains | Optional[List[str]] | Domains to exclude from the search. | None |
| start_crawl_date | Optional[str] | Deprecated and will be removed in a future release. Only links crawled after this date. | None |
| end_crawl_date | Optional[str] | Deprecated and will be removed in a future release. Only links crawled before this date. | None |
| start_published_date | Optional[str] | Only links published after this date. | None |
| end_published_date | Optional[str] | Only links published before this date. | None |
| include_text | Optional[List[str]] | Strings that must appear in the page text. | None |
| exclude_text | Optional[List[str]] | Strings that must not appear in the page text. | None |
| type | Optional[Union[[SearchType](#searchtype), str]] | Search type - 'auto' (default), 'fast', 'deep-lite', 'deep', 'deep-reasoning', 'neural', 'instant', or 'lite' (beta: low-cost, reduced parameter set). | None |
| category | Optional[[Category](#category)] | Data category to focus on (e.g. 'company', 'news', 'publication'). | None |
| flags | Optional[List[str]] | Experimental flags for Exa usage. | None |
| moderation | Optional[bool] | If True, the search results will be moderated for safety. | None |
| user_location | Optional[Union[str, [UserLocation](#userlocation)]] | The end user's location, as a two-letter ISO 3166-1 country code or a [UserLocation](#userlocation) dict. | None |
| additional_queries | Optional[List[str]] | Alternative query formulations for deep search to skip automatic LLM-based query expansion. Max 5 queries. Only applicable when type is 'deep-lite', 'deep', or 'deep-reasoning'. Example: ["machine learning", "ML algorithms", "neural networks"] | None |

Must not contain personal information such as an email address, phone number, username or name. Hash such values before sending them. 1 to 64 characters: letters, digits, ``_`` and ``-``. Retained even when your team has Zero Data Retention enabled. Does not affect results. | None |
| betas | Optional[Sequence[str]] | Exa-Beta tokens to send with the request (e.g. ``[DYNAMIC_HIGHLIGHTS_BETA]`` for Dynamic Highlights). | None |
| extra_body | Optional[Mapping[str, Any]] | Per-call body overrides, except stream. | None |
| timeout | Optional[float] | Per-operation network inactivity timeout in seconds. Defaults to the client timeout. | None |
| extra_headers | Optional[Mapping[str, Optional[str]]] | Extra headers to send with the request. | None |
| extra_query | Optional[Mapping[str, Any]] | Extra query parameters to send with the request. | None |

## `find_similar` Method

DEPRECATED METHOD: find_similar()/findSimilar is deprecated. Use search() instead.

Migration:
    Use search("pages similar to " + url) instead of find_similar(url).

Finds similar pages to a given URL, potentially with domain filters and date filters.

By default, returns text contents with 10,000 max characters. Use contents=False to opt-out.

### Input Example

```python
url = "https://www.miniclip.com/games/en/"
similar_results = exa.search(
    f"pages similar to {url}",
    num_results=2,
```

## `answer` Method

Generate an answer to a query using Exa's search and LLM capabilities.

### Input Example

```python
response = exa.answer("What is the capital of France?")

print(response.answer)       # e.g. "Paris"
print(response.citations)    # list of citations used

# If you want the full text of the citations in the response:
response_with_text = exa.answer(
    "What is the capital of France?",
    text=True
)
print(response_with_text.citations[0].text)  # Full page text
```

| Parameter | Type | Description | Default |
| --------- | ---- | ----------- | ------- |

| system_prompt | Optional[str] | A system prompt to guide the LLM's behavior when generating the answer. | None |
| model | Optional[Literal['exa', 'exa-pro']] | The model to use for answering. Defaults to None. | None |
| output_schema | Optional[[JSONSchemaInput](#jsonschemainput)] | JSON schema describing the desired answer structure. | None |
| user_location | Optional[Union[str, [UserLocation](#userlocation)]] | The end user's location, as a two-letter ISO 3166-1 country code or a [UserLocation](#userlocation) dict. | None |

## `stream_answer` Method

Generate a streaming answer response.

### Input Example

```python
stream = exa.stream_answer("What is the capital of France?", text=True)

for chunk in stream:
    if chunk.content:
        print("Partial answer:", chunk.content)
    if chunk.citations:
        for citation in chunk.citations:
            print("Citation found:", citation.url)
```

| dynamic | bool | Enable Dynamic Highlights (research preview): allocates one shared context budget across all results instead of a per-document budget; the model sizes the output itself. #### `ApiWarning`

A warning the Exa API returns about a request, such as a field it ignores.

A warning never changes the status code or the result. It is for whoever
owns the code that builds the request: fix the request, and do not pass the
warning to a model. Today /search returns them, in its response and stream.

| Field | Type | Description |
| ----- | ---- | ----------- |
| code | str | Machine-readable code in UPPER_SNAKE case, such as 'IGNORED_FIELD' (the field is accepted and has no effect). The set of codes is open, so handle codes you do not know. |
| path | str | JSON Pointer to the request field the warning is about, such as '/startCrawlDate'. |
| message | str | What to change in the request, in plain words. |

#### `SearchNotice`

A note about how the results of a search were produced.

For example, a query restriction relaxed to return results. A notice is
written to be shown to a model. Pass its `message` to the model that reads
the results.

| Field | Type | Description |
| ----- | ---- | ----------- |
| code | str | Machine-readable code in UPPER_SNAKE case, such as 'RESTRICTIONS_RELAXED' (no results matched a restriction in the query, so the results come from a search with it removed). The set of codes is open, so handle codes you do not know. |
| path | str | JSON Pointer to the request field the notice is about, such as '/query'. |
| message | str | Complete on its own and written to be shown to a model. |
| details | Optional[Dict[str, Any]] | Extra context, with keys as the API sent them. No schema is promised for its keys, and it never carries information that `message` lacks. |

### Entity Types

These types represent structured entity data returned for company or person searches.

#### `JSONSchemaInput`

Input type for JSON schema parameters. Can be either a Pydantic model class (automatically converted to JSON Schema) or a raw JSON Schema dictionary.

**Type:** Union[type[[BaseModel](https://docs.pydantic.dev/latest/api/base_model/#BaseModel)], dict[str, Any]]

#### `Category`

Data category to focus on when searching. Each category returns results specialized for that content type.

**Type:** Literal['company', 'news', 'publication', 'personal site', 'financial report', 'people']

#### `SearchType`

Search type that determines the search algorithm.

We recommend 'lite', 'auto' and 'deep'. 'fast', 'instant' and
'deep-reasoning' are legacy search types. They are still accepted, and each
has an alternative. Use 'lite' instead of 'instant'. Use 'lite' instead of
'fast', or 'auto' when the request needs parameters 'lite' rejects. Instead
of 'deep-reasoning', use 'deep', or Exa Agent for long-running research,
list building and multi-hop enrichment. Start an Exa Agent run with
``exa.agent.runs.create``.

'auto' (default) automatically selects the best approach, 'fast' prioritizes
speed, 'deep-lite', 'deep', and 'deep-reasoning' are deep-search variants,
'neural' uses embedding-based semantic search, and 'instant' uses low-latency
neural search. 'lite' (beta) is a low-cost search that supports a reduced set
of parameters.

Search methods also accept any other string as ``type`` and pass it through
to the API as given.


**Type:** Literal['auto', 'fast', 'deep-lite', 'deep', 'deep-reasoning', 'neural', 'instant', 'lite']

#### `DeepOutputSchema`

Search output schema.

- ``{"type": "text", "description": ...}`` returns plain text in ``output.content``.
- ``{"type": "object", ...}`` returns structured JSON in ``output.content``.

For object schemas, the API enforces max nesting depth 2 and max 10 total properties.


**Type:** Union[[DeepTextOutputSchema](#deeptextoutputschema), [DeepObjectOutputSchema](#deepobjectoutputschema)]

#### `UserLocation`

The end user's location, as a dict with ``country``, a ``latitude`` and
``longitude`` pair, or both.

``user_location`` also takes a two-letter ISO 3166-1 country code string, e.g.
``"US"``. The country localizes results. Coordinates are used only for queries
that name no place but depend on where the user is, such as "coffee near me".
They do not set a country, so send ``country`` with them to localize results.
Send only the precision your use case needs.


**Type:** Union[[UserLocationCountry](#userlocationcountry), [UserLocationCoordinates](#userlocationcoordinates)]

- compact: Most concise output, main content only (default)

**Type:** Literal['compact', 'standard', 'full']
